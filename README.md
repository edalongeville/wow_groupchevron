# GroupChevron

A World of Warcraft addon (Interface 16001, WoW: Forever client) that makes the members of your party or raid easy to spot in a crowd.

This repository was split out of [myforeverjourney](https://github.com/edalongeville/myforeverjourney), where the addon was an optional, fully independent component.

## Layout

| Path | Content |
|---|---|
| `GroupChevron/` | the addon: `Core.lua` (pure, unit-tested logic), `GroupChevron.lua` (WoW glue), `.toc`, `chevron.tga`, `icon.tga` |
| `spec/` | [busted](https://lunarmodules.github.io/busted/) tests (`Core.lua` and a smoke test of the glue against a stubbed WoW API) |
| `tools/` | generators for `chevron.tga` and `icon.tga` (Python 3, no dependencies) |
| `.luacheckrc` | luacheck configuration (Lua 5.1, WoW globals) |

## Features
A small, separate addon that makes the members of your party or raid easy to spot in a crowd: their nameplate name turns magenta pink (`#FF4FD8`; nothing in the default UI uses it for units) and a discreet fading double down-chevron (two stacked "V", the lower one at 50 %, about 10 × 9 px, in the same colour) sits 2 px above it. **Friends** outside the group (on your character friends list, or a Battle.net friend's character) get their name in blue (`#3FA7FF`, configurable) and the same chevron in that colour (optional); once they join your group they get the member look. **Guildmates** outside the group (and not on your friends list) get their name in green (`#40FF40`, configurable) and the same chevron in that colour (optional). With **compact** on (the default), the other friendly players show **only their name** (the game's colour), plus their health bar while they are hurt, so the friendly nameplates no longer clutter the screen; targeting one of them shows their full plate. With **class colour** on (off by default), those other friendly players' names are drawn in their class colour, as in Blizzard's default UI. Friendly players outside the group (friends, guildmates and class-coloured ones included) show their **level** after their name on name-only (compact) plates, e.g. `Garzak (19)` (`showlevel`, default on); wherever their health bar is shown (full plates, your target, a hurt compact plate), Blizzard's level beside the bar replaces it. Everyone else's plate (enemies, NPCs, the target) is left as the game draws it.

- **Standalone:** no events, no uploads, no dependency on any other addon. Its version is the `## Version` in `GroupChevron/GroupChevron.toc` (bump it with every change).
- **Install:** copy the `GroupChevron` folder into `World of Warcraft/<flavor>/Interface/AddOns/` (e.g. `_classic_era_`). Its settings live in `WTF/` (`GroupChevronDB`) and survive removal.
- **Needs the friendly player nameplates** (`V` / `Shift+V`); at login it says so once in chat when they are off.
- **`/gchev`**: prints the state (on/off, colour, which name field was found, plates marked, compact on/off and plates in compact mode). `/gchev on` / `off` (off restores the names' colour at once), `/gchev color #RRGGBB` (invalid input is refused and changes nothing), `/gchev chevsize <1-5>` (chevron size factor; since 0.6.1 the bar also widens: Blizzard stretches `HealthBarsContainer` between the top corners of `CastBarsContainer`, and nameplate regions cannot be measured (`GetPoint`/`GetWidth` fail with "Can't measure restricted regions"), so it is laid out again from Blizzard's own layout values (`NamePlateSetupOptions.castBarToHealthBarSpacing` and `insetWidth`, `NamePlateDriverFrame:GetNamePlateWidth`) with offsets from `Core.BarOffsets`, about its centre, bottom unchanged, and laid out back the same way at size 1 (any of those missing: height only, one chat notice); a bar at size 1 is never re-anchored; `buffsize` above 1 also lifts a member's name, and so the chevron, by half of what a buff icon gains (`Core.BuffLift`, from `NamePlateConstants.AURA_ITEM_HEIGHT` and the aura frame's `auraItemScale`), since Blizzard centres the buffs on the left of the bar), `/gchev othersize <1-3>` and `/gchev otherbarsize <1-3>` (name text and health bar size of friendly players outside the group: the name-only plates of compact mode and, since 0.17.1, the full plates of friends, guildmates and class-coloured players when compact is off; without a value they print the current one; `textsize` scales the addon's own name frame (see Full name below), never Blizzard's font; `/gchev friendcolor #RRGGBB` (friends' colour, default `#3FA7FF`; `/gchev guildcolor #RRGGBB` (guildmates' colour, default `#40FF40`) and `/gchev guildchevron on` / `off` (default on), same validation; `/gchev level on` / `off` (the level after friendly players' and guildmates' names, default on; same validation); `/gchev compact on` / `off` (name-only plates for friendly non-members, default on; anything else is refused and changes nothing; without a value it prints the current one; off restores every plate at once, so does `/gchev off`); `/gchev classcolor on` / `off` (also `classcolour`; other friendly players' names in their class colour, default off; same validation, without a value it prints the current one; `/gchev` prints it with the number of plates coloured); `/gchev reset` (default member colour only), `/gchev options` (opens the settings page, see below; a message, never an error, when the client has no Settings canvas API or refuses it, e.g. in combat), `/gchev names` (changes nothing, needs no target: lists every visible plate whose Blizzard name is not visible (alpha below 1, or hidden) and not covered by the addon's own name, with its unit, alpha, shown state and whether the addon still remembers fading it, then the driver hook call counts and the failed name restores), `/gchev debug` (on the current target's plate: the name field found, whether the target counts as a group member, whether it counts as a friend and which source answered (character list, Battle.net, none, no readable GUID, API missing; `/gchev` prints the same for the current target), whether it counts as a guildmate and which API answered, Blizzard's name alpha and shown state on that plate, whether the addon's name covers it, the faded names still pending, whether the nameplate driver hooks are installed and how often they ran, and the number of failed name restores, its class token and class colour (`unknown` / `none` when they cannot be read), the `classcolor` setting and the colour its name gets (member, friend, guild, class or Blizzard's), its mode, and the parts compact mode hides there, or would hide since the target itself is always shown in full, each with its name (frame name, else its field on `UnitFrame` or the name's ancestors) and object type: this is how to check which parts exist on the Forever client). Changes apply at once to the visible plates and are saved in `GroupChevronDB` (`enabled`, `color` = `{ r, g, b }` in 0..1, `chevsize` = 1..5, `textsize`, `barsize`, `buffsize`, `othersize`, `otherbarsize` = 1..3, `compact` = boolean, invalid = on; `friendcolor` = `{ r, g, b }`, invalid = `#3FA7FF`; `friendchevron`, `bnetfriends` = boolean, invalid = on; `guildcolor` = `{ r, g, b }`, invalid = `#40FF40`; `guildchevron` = boolean, invalid = on; `classcolor` = boolean, invalid = off; `showlevel` = boolean, invalid = on).

The panel and the slash commands call the same setters (`SetEnabled`, `SetCompact`, `SetColor`, `SetFriendColor`, `SetGuildColor`, `SetFlag`, `SetFactor`, `ResetAll`), which validate through `Core`, save, and refresh the plates at once; the panel reads `GroupChevronDB` each time it is shown. - **Friends (0.8.0):** a relation layer on top of the modes, in priority order group member > friend > guildmate > class colour. A friend is a friendly player (`UnitIsPlayer`, `UnitIsFriend("player", unit)`, not you, known not to be a group member) whose `UnitGUID` is on the character friends list (`C_FriendList.IsFriend(guid)`) or, with `bnetfriends` on, a Battle.net friend's character (`C_BattleNet.GetAccountInfoByGUID(guid).isFriend == true`; not even asked with the setting off) (`Core.FriendLookup`, `Core.Relation`; none of these APIs is verified on the Forever client: a missing function, an error or a secret value means "not a friend", and the plate keeps the look it has without this layer). `Core.PlateMode` returns the mode and the relation: a friend who is your target, or any friend with compact off, gets mode **friend** (Blizzard's full plate, our own name in the friend colour, the chevron when `friendchevron` is on; since 0.17.1 the name and the health bar use `othersize` / `otherbarsize` when compact is off, and since 0.17.2 also for your target with compact on; the member sizes never apply); a non-target friend with compact on stays a **compact** plate (name only, health bar while hurt, `othersize` / `otherbarsize`), now in the friend colour and with the chevron. The chevron is the member one (same texture, geometry, `chevsize`) tinted with the friend colour. The record of Blizzard's colour is kept across member ↔ friend changes (`marks`, keyed by `UnitFrame`), so leaving every marked mode (unfriended, target change, recycling, removal, settings change, `/gchev off`) gives Blizzard's colour and alpha back. The visible plates are re-checked on `FRIENDLIST_UPDATE`, `BN_FRIEND_LIST_SIZE_CHANGED`, `BN_FRIEND_INFO_CHANGED` and `BN_FRIEND_ACCOUNT_ONLINE` / `OFFLINE` (each registered under `pcall`, an unknown event is skipped), coalesced into one `RefreshAll` per burst 0.2 s later (`C_Timer.After`; without it, at once). Not verified in game yet: check with `/gchev debug` on a friend.
- **Guildmates (0.11.0):** the next relation after friend: priority group member > friend > guildmate (a friend who is also a guildmate is shown as a friend). A guildmate is a friendly player (same conditions as a friend, but not on the friends list) for whom `Core.GuildLookup` says yes: only when `IsInGuild()` is true (otherwise no guild API is called), `UnitIsInMyGuild(unit)`, and only when that function does not exist, `IsPlayerInGuildFromGUID(UnitGUID(unit))` (global, else `C_PlayerInfo`). A missing function, an error or a secret value means "not a guildmate" (none of these is verified on the Forever client). `Core.PlateMode` treats the `guild` relation like `friend` (target keeps the mark with the full plate; compact on/off as for friends), in `guildcolor` with the chevron when `guildchevron` is on. The plates are re-checked on `PLAYER_GUILD_UPDATE` and `GUILD_ROSTER_UPDATE`, coalesced with the friend list events into one `RefreshAll` per burst. `/gchev debug` (and `/gchev`) print whether the target counts as a guildmate and which API answered.
- **Sizes on full plates (0.17.1):** `othersize` and `otherbarsize` now also apply to the full plates of friends, guildmates and class-coloured friendly players when compact is off (name and health bar). They used to apply only to compact plates, so with compact off these plates stayed at size 1. Your target with compact on keeps size 1, group members keep `textsize` / `barsize`, and the default of 1 changes nothing.
- **Sizes on the target (0.17.2, #298):** `othersize` and `otherbarsize` apply to every friendly player outside the group (`Core.OtherSizes`: friendly, not a member, not you; compact and the target state do not matter), so their name and health bar no longer jump back to size 1 when you target them with compact on. This also covers a plain friendly (no friend, guildmate or class colour) on a full plate, compact on (the target) or off: the addon draws its name in Blizzard's colour at `othersize` when the level follows it or `othersize` is not 1 (else Blizzard's name stays), and scales its health bar to `otherbarsize` when it is not 1. Any other default plate (enemies, NPCs) gets its original scales back, so a pooled `UnitFrame` never keeps a friendly's bar size. Not verified in game yet.
- **Name height (0.18.0, #300):** `/gchev namegap <-10..40>` (group members) and `/gchev othernamegap <-10..40>` (every friendly player outside the group, wherever `othersize` applies: compact plates and full plates, the target included) move the addon's own name label up (positive) or down (negative) from where Blizzard puts its name above the health bar, in whole UI points (not scaled by the text size), default `0` = the layout as before. Also a "Name height" slider in the **Group members** and **Friendlies** groups of the settings page (step 1, applied on release), reset to 0 by **Reset to defaults**. Saved as `GroupChevronDB.namegap` / `othernamegap` (a whole number in -10..40; missing or invalid = 0; decimals and out-of-range values are refused with a message, no clamping, `Core.ValidGap` / `ParseGap` / `SnapGap`). The anchor offset is `(buff lift + gap) / text size` (`Core.NameOffset`), so for members it adds to the `buffsize` lift, and the chevron, anchored on the name, moves with it. Only the addon's own name moves: on a plain friendly's full plate with level off and `othersize` 1, a non-zero `othernamegap` makes the addon draw the name (in Blizzard's colour) so it can move; where the addon's name cannot be drawn (unreadable text or font) Blizzard's name stays where it is. Not verified in game yet, in particular with enlarged bars and buffs.
- **Localisation (0.15.0):** the settings page texts (group titles, labels, checkboxes, sliders, Reset button) come from `Core.Locales` by `GetLocale()`: `enUS` and `frFR`; any other locale, or a key missing from the locale, shows the English text (`Core.Translate`, never an error). The addon name, the font names, chat output and `/gchev` help stay English. The French wording is unreviewed and not yet checked in game for overlaps.
- **Name font (0.14.0):** `/gchev font default|outline|chat|large|game13` (also a drop-down on the settings page listing them, or a button that cycles through them if the client has no `UIDropDownMenu` API; saved as `GroupChevronDB.font`, invalid = `default`) picks the font of the addon's own name labels from client font objects (`Core.FONTS`: `SystemFont_Outline`, `ChatFontNormal`, `GameFontNormalLarge`, `Game13Font_o1`), for readability on bright terrain. `default` keeps Blizzard's own name font as before. Font objects rather than file paths keep the client's Cyrillic/Korean/Chinese fallbacks; a missing global falls back to `default`. It only applies to our FontString (`SetFontObject`), never to Blizzard's name. Not verified in game yet: check the object names exist on the Forever client.
- **Chevron size up to 5 (0.9.0):** `chevsize` alone goes from 1 to 5; every other factor (`textsize`, `barsize`, `buffsize`, `othersize`, `otherbarsize`) stays 1 to 3. `Core.MaxFactor(kind)` gives the per-kind maximum used by validation, parsing, snapping, `InitDB`, the slider range and the slash command help/error text. A saved `chevsize` already in 1..3 is kept; above 5 it is reset to the default, same as any other out-of-range value.
- **Class colour (0.10.0):** with `classcolor` on, a friendly player who is neither a group member, a friend, a guildmate nor you gets their name in their class colour, whether compact is on or off and also as your target. The colour of a plate's name comes from `Core.NameColor` (pure, tested), in priority order member > friend > guild > class colour > Blizzard's colour, so members, friends and guildmates keep their own colour. The class token is the second result of `UnitClass(unit)` (e.g. `MAGE`) and the colour the client's own: `C_ClassColor.GetClassColor(token):GetRGB()`, else `RAID_CLASS_COLORS[token]` (`.r/.g/.b`), never a table of ours (`Core.ClassColor`; asked only with the setting on). A missing function, an error, a secret value or an unknown token gives no class colour: the name keeps the look it has without the setting. Modes: a non-target friendly with compact on stays a **compact** plate, its name in the class colour (at `othersize`); the target, or any friendly with compact off, gets mode **class**: Blizzard's full plate with only the name drawn by the addon's own FontString in the class colour (no chevron; since 0.17.1 the name and the health bar use `othersize` / `otherbarsize` when compact is off, and since 0.17.2 also for your target with compact on). Both reuse the friend path (`Mark`, records keyed by `UnitFrame`), so turning the setting off, leaving the mode, recycling or removal gives Blizzard's name, colour and alpha back as before. None of these APIs is verified on the Forever client: check with `/gchev debug` on a friendly player.
- **Level (0.12.0):** with `showlevel` on (default), a friendly player who is not a group member and not you (`Core.ShowsLevel`: friends, guildmates and class-coloured friendlies included, compact on or off, your target too) shows `<name> (<level>)` (`Core.NameWithLevel`): `UnitLevel(unit)` of 1 or more as is, `-1` or less (unknown to the client) as `(??)`; a level that is not readable (missing function, error, secret value, non-integer, 0) gives the name alone (`Core.UnitLevel`). The level is part of the addon's own name text (see Full name below), so it has the name's colour (member, friend, guild, class or Blizzard's), size (`othersize` on compact plates and, since 0.17.1, on the full plates of friends, guildmates and class-coloured players with compact off; since 0.17.2 on every friendly non-member's full plate, your target included) and font object; Blizzard's name text is never changed. On a full non-member, non-friend, non-guild, non-class plate (compact off, or the target), the name is drawn by the addon's own FontString only while a level is shown or `othersize` is not 1 (Blizzard's colour, `othersize`; the rest of the plate stays Blizzard's but the health bar, at `otherbarsize`), and Blizzard's name gets its alpha back otherwise. Our name stays centred on Blizzard's, and the chevron stays anchored on its top. Refreshed by the name-update hook and by `UNIT_LEVEL` for a nameplate unit (registered under `pcall`). Not verified in game yet. **Only while the bar is hidden (0.19.0, #301):** Blizzard's health bar shows the level beside it, so the suffix is now left out wherever that bar is visible. Full plates (compact off, your target, friends', guildmates' and class-coloured full plates) never get it: on a plain friendly's full plate the addon's own name is then drawn only when `othersize` or `othernamegap` is not the default. A compact plate gets it only while its health bar is hidden (full health), the same `/gchev level` setting: `Core.LevelSuffix` decides. With the health curve (secret health), the bar's state cannot be read, so the addon draws two labels of the same look on the same spot, the name with the level and the name alone (`rec.short`, created only for a level), and the client drives them: the name alone gets the bar's alpha, the name with the level that of the opposite curve (`Core.FULL_HEALTH_CURVE_POINTS`: 0 below full health, 1 at full health, built once, only when needed), both re-applied on every `UNIT_HEALTH` / `UNIT_MAXHEALTH`, never read or compared. Without the curve the readable-health fallback picks the text (`hurt`: name alone). In doubt the suffix stays: the curve failing, the bar refusing the secret alpha (name only), a label refusing it, or no health bar part. Blizzard's name handling (`SyncName`, `fadedNames`) is unchanged. Not verified in game yet: check that a compact friendly's suffix goes when hurt and comes back once healed.
- **Compact mode:** each visible plate gets a mode from `Core.PlateMode` (pure, tested), fed by `Core.UnitInfo`: **member** (group member: full plate, pink name, chevron), **compact** (a player, not you, `UnitIsFriend("player", unit)`, not a group member, not your target (`UnitIsUnit(unit, "target")`), compact on: name only) or **default** (everything else, including the addon off, compact off and any API error, missing function or secret value: the plate exactly as the game draws it; an unknown group membership never gives compact). There is no per-plate "name only" setter, so compact fades out, with `SetAlpha(0)`, everything in `UnitFrame`'s tree but the name: for the name FontString and each of its ancestors up to `UnitFrame` (`GetParent()`), the ancestor's other child frames and regions (`GetChildren()`, `GetRegions()`); no fixed list of field names. While the unit is hurt, `UnitFrame.HealthBarsContainer` and `UnitFrame.healthBar` are shown too. **Secret health (0.16.0, #284):** on the Forever client `UnitHealth`, `UnitHealthMax` and `UnitHealthPercent` are secret values, which Lua cannot compare or test, so the bar's alpha is computed by the client: a colour curve built once (`Core.HealthCurve`: `C_CurveUtil.CreateColorCurve()` with `CreateColor`, white, alpha 1 at 0 and 0.999 of full health, 0 at full health) is evaluated by `UnitHealthPercent(unit, false, curve)` (`Core.HealthAlpha`), and the 4th value of the colour's `GetRGBA()` (secret) is passed straight to the health bar parts' `SetAlpha` under `pcall`, never read, compared or stored as a key (checked in game on the targeted plate's `HealthBarsContainer`; a frame that refuses a secret alpha gets `SetAlpha(0)`, name only). Because the alpha cannot be compared, `UNIT_HEALTH` / `UNIT_MAXHEALTH` re-apply it on every event, and the parts' `OnShow` hook re-applies it too. Without that API, or when it fails, the readable-health fallback of up to 0.15.0 applies (`Core.HealthMissing`: `UnitHealth < UnitHealthMax`, both readable; an error or a secret value counts as full health, so the plate stays name-only): `UNIT_HEALTH` / `UNIT_MAXHEALTH` re-check a compact plate only when its unit crosses "full" either way. Either way a part no longer to fade gets its alpha back at once. `/gchev debug` prints the target's `UnitHealth`, `UnitHealthMax` and `UnitHealthPercent` (`secret` instead of a secret value), whether the curve works, and the shown state and alpha of its health bar parts. It never hides or moves the plate, `UnitFrame`, the name or its ancestors (clicks and stacking keep working), nor the addon's own chevron. What it faded is recorded per `UnitFrame` (not per plate: since 0.6.2, see below) in weak-keyed tables and given alpha 1 back as soon as the plate leaves compact mode (member, target, another unit after recycling, removal, `compact off`, `/gchev off`). Each faded frame gets one `OnShow` hook (never two) that fades it again only while its plate is still compact (e.g. the cast bar), and parts that appear later are caught on the next name update. The mode is re-checked in the `CompactUnitFrame_UpdateName` hook and on `NAME_PLATE_UNIT_ADDED`, `GROUP_ROSTER_UPDATE` and `PLAYER_TARGET_CHANGED` (the old and the new target both change). Forbidden plates (friendly plates in dungeons and raids) are skipped silently. Not verified in game yet. **UnitFrame pooling (0.6.2):** Blizzard pools the `UnitFrame`s apart from the plates (`NamePlateBaseMixin:AcquireUnitFrame` on `NAME_PLATE_UNIT_ADDED`, `ReleaseUnitFrame` on removal), so the `UnitFrame` a plate shows changes each time the plate is reused. Everything the addon changes lives on the `UnitFrame` (faded name and parts, scales, bar layout, and its own name and chevron frames, created as children of it), so every record is keyed by the `UnitFrame`, and the `CompactUnitFrame_UpdateName` hook also unmarks a `UnitFrame` that now shows a default plate (an enemy, say), while `RefreshAll` cleans every `UnitFrame` no plate shows. That was not enough (0.7.1): the `NAME_PLATE_UNIT_ADDED` / `REMOVED` handlers may run before or after Blizzard's (at removal the plate may already have given its `UnitFrame` back; at addition it may not have one yet), and Blizzard does not call `CompactUnitFrame_UpdateName` when it gives a `UnitFrame` a unit (`CompactUnitFrame_UpdateAll` skips it), so a `UnitFrame` could still reach an enemy with Blizzard's name faded (`alpha 0`, seen in game). GroupChevron now post-hooks Blizzard's nameplate driver (`NamePlateDriverFrame`, when it has these methods): `ReleaseUnitFrame(base)` undoes everything on `base.UnitFrame` before it goes back to the pool, and `OnNamePlateAdded(token)` applies the plate's mode once it has its `UnitFrame` and unit; the event handlers stay as a fallback. Up to 0.6.1 the records were keyed by plate: a `UnitFrame` could come back from the pool under another plate with Blizzard's name still faded (enemies without a name), and a plate's own name was drawn inside the first `UnitFrame` it ever had (invisible once that one was back in the pool). **Names given back (0.12.1):** the same symptom came back on 0.12.0, this time on the *target's* plate, which every target change refreshes, so not a missed moment: the record of the fade was wrong. Up to 0.12.0 the alpha to give back was read with `GetAlpha` when the name was faded, and the record was dropped whatever the `SetAlpha` that gave it back did (errors are swallowed); one fade not given back was then read as "originally 0" and given back as 0 on every later unit of that `UnitFrame`. Now Blizzard's name is always given alpha 1 (Blizzard's nameplate code never sets the name's alpha: Blizzard_NamePlates and CompactUnitFrame, 12.1.5 UI source), every name we faded is remembered (`fadedNames`) until a `SetAlpha(1)` is known to have worked (else chat says so once, and it is retried by every `RefreshAll` and on `PLAYER_REGEN_ENABLED`), and every refresh of a plate ends with `SyncName`, which gives Blizzard's name alpha 1 unless the addon's own name covers it right now, even when applying the mode raised an error. `spec/groupchevron_spec.lua` also runs a model of Blizzard's driver (pooling, either event order, combat with failing `SetAlpha(1)`) and checks after every step that each plate shows a name.
- **How:** it listens to `NAME_PLATE_UNIT_ADDED` / `REMOVED`, `GROUP_ROSTER_UPDATE`, `PLAYER_TARGET_CHANGED`, `PLAYER_ENTERING_WORLD`, `ADDON_LOADED` and the friend list events above. A unit is a member when `UnitIsPlayer`, not `UnitIsUnit(unit, "player")`, and `UnitInParty` or `UnitInRaid` (`Core.IsGroupMember`; an error or a secret value counts as "no"). The name FontString is `UnitFrame.name`, else `.Name`, else `.unitName` (unverified on the Forever client; without one, only the chevron is drawn, anchored to the top of `UnitFrame`, and chat says so once). Blizzard recolours names on its own updates, so the colour is re-applied from a `hooksecurefunc` on `CompactUnitFrame_UpdateName` (nameplate frames of group members only). The chevron is a child of `plate.UnitFrame` (it fades and hides with the plate), drawn from two copies of `GroupChevron/chevron.tga` (64 × 32, one white anti-aliased "V" with alpha, coloured with `SetVertexColor`, pixel snapping off so it scales smoothly with `chevsize`), created once per plate and cached in a weak-keyed table; if the client cannot load the texture (e.g. the addon was updated while the game ran: new files need a restart), chat says so once and four rotated `SetColorTexture` rectangles are drawn instead. The texture is generated by `tools/chevron_tga.py` (`python3 tools/chevron_tga.py GroupChevron/chevron.tga` from the repository root). **Full name:** Blizzard's name FontString is as wide as the health bar, so long or enlarged names end in "…". On the plates the addon handles (members, friends, compact non-members and friendly players in their class colour), the name is drawn by the addon's own FontString (a child frame of `UnitFrame`, kept visible by compact mode), anchored on the bottom centre of Blizzard's name, without a width limit, with Blizzard's font object (`SetFontObject(name:GetFontObject())`, so the same alphabet fallbacks: Cyrillic, Korean and Chinese names render; `GetFont` values only when there is no font object; `textsize` is the scale of its frame, never a `SetFont` size), shadow and text (copied on every name update), in pink for members and Blizzard's colour otherwise; Blizzard's name is faded with `SetAlpha(0)` and gets its alpha back when the plate leaves those modes. A name text that cannot be read (error or secret value) or a hidden name leaves Blizzard's name as it was (truncated, but never missing). The addon never calls `SetFont` on Blizzard's name: up to 0.4.0 it did for `textsize`, which replaced the name's font object by a single font file without Cyrillic glyphs, so Russian names showed as boxes, also on recycled plates until the next reload. Plates are recycled: a plate that stops showing a member loses its chevron and gets back the colour it had before. The geometry constants are at the top of `GroupChevron.lua`. Not verified in game yet.
- **AddOns-list icon:** `GroupChevron.toc` has `## IconTexture: Interface\AddOns\GroupChevron\icon` (no extension) and `GroupChevron/icon.tga` is the pink (`#FF4FD8`) double chevron, 64×64, 32-bit TGA with alpha, second stroke faded, on a transparent background. Unlike `chevron.tga` (white, tinted at runtime with `SetVertexColor`) it is pre-coloured, because the AddOns list cannot tint it. Regenerate from the repository root with `python3 tools/groupchevron_icon_tga.py GroupChevron/icon.tga` (same V geometry as `chevron_tga.py`). Whether the WoW: Forever client reads `IconTexture` is not verified in game; if not, the field is ignored.

## Development

Lua 5.1, as in the WoW client. Keep logic that does not need the WoW API in `Core.lua`, with tests in `spec/`.

```bash
luacheck . && busted --lua=lua5.1 spec
```

Regenerate the textures from the repository root:

```bash
python3 tools/chevron_tga.py GroupChevron/chevron.tga
python3 tools/groupchevron_icon_tga.py GroupChevron/icon.tga
```

Bump `## Version` in `GroupChevron/GroupChevron.toc` with every change to the addon (patch for fixes, minor for features).
